# CNO — Chief Naming Officer v2.1

상품 등록 표준화 에이전트. 상품명 **사실검증**과 **브랜드 · 부가제목 · 키워드 · 중요요약설명 자동 생성**을 한 화면에서 처리한다. **Romi Lab** · Rom Kim (romi4670)

**Live:** https://romi4670.github.io/cno/

## 무엇을 하나

이커머스 상품 등록에서는 상품마다 공식 사양을 찾아 키워드와 20여 항목의 중요요약설명을 직접 입력해야 한다. 담당자마다 표기가 다르고, 다른 상품의 값을 복사해 붙이거나 사양을 잘못 옮겨 적는 오류가 생긴다. CNO는 이 반복 입력을 **규칙과 검증된 사양 DB**로 대신하고, 등록 전에 사실 오류를 잡아낸다.

## 사용

두 가지 입력 중 **하나만** 쓰면 된다. 입력하면 바로 실행된다.

1. **방법 1 · 캡처 넣기:** 신관리자 상품정보·상품 목록 화면을 캡처해 끌어다 놓거나 `Ctrl+V`로 붙여넣는다(영역을 클릭할 필요 없음). 저장해 둔 이미지 파일은 **파일에서 선택**으로 올린다. 브라우저 안에서 글자를 인식해 상품명 등을 채운다. 인식된 **상품명 칸을 원본과 한 번 대조**한다.
2. **방법 2 · 상품명 입력:** 상품명만 입력. A/S 기간(확인된 경우만)과 쿨러 포함 여부는 보조 옵션으로 지정할 수 있다.
3. 필요하면 **기존 정보와 비교**를 펼쳐 현재 등록값(제조사·브랜드·부가제목·키워드·중요요약)을 넣는다. 키워드 혼입, 쿨러 충돌, 사양 불일치를 함께 점검한다.
4. 왼쪽 **등록용 결과**를 복사 버튼으로 관리자 화면에 붙여넣는다. 오른쪽 **검증 결과 및 근거**에서 판정과 근거를 확인한다.

화면 하단 **예제로 체험하기**는 실제 업무에서 나온 오류 유형을 공개 모델명으로 재현한 것이다.

### 캡처 인식 방식

- 캡처에서는 **모델 번호와 판매구성만** 사용한다. 한글 코드네임 등 나머지는 사양 DB와 규칙으로 생성하므로 인식 오류가 결과 값에 섞이지 않는다.
- 서버 형식 `(48C, 96T …)`의 글자 오인식은 "스레드 = 코어 × 1 또는 × 2"가 맞을 때만 자동 교정한다.
- 서버 `Processor` 상품명 앞의 5자리 숫자(끝 0)는 인텔 모델 형식(4자리 + P·E)에 맞지 않아 `P`로 보정하고 **확인 요청**으로 표시한다(예: `67470` → `6747P`).
- 캡처의 작은 글씨(키워드 줄 등)는 잘못 읽히기 쉬워, 이상한 글자가 섞인 항목은 비교에서 제외한다. 정확한 점검은 원본 키워드를 "기존 정보와 비교"에 직접 붙여넣는다.
- 이미지는 외부로 전송되지 않는다. 인식 엔진(Tesseract.js)과 한국어 데이터를 **최초 1회 CDN에서 내려받는다.** 사내망에서 CDN이 막혀 있으면 캡처 입력이 동작하지 않으며, 이때는 방법 2를 쓴다.

## 1단계 · 상품명 검증

- **CPU: 보존 모드.** 현행 상품명 형식(`모델명 (코드네임) (판매구성)`, 서버 `모델 Processor (xC, yT, zM Cache, a.bc GHz)`)은 그대로 두고, **사실 오류만 '확인 요청'**으로 표시한다. 상품명은 자동으로 고치지 않는다(상품명은 담당 승인 사항).
  - 코드네임 사실 오류와 표기 변형, 서버 형식 내부 오류(`GHz` 띄어쓰기, 소수점)
  - 상품명 ↔ 부가제목 쿨러 충돌, 제조사 ↔ 브랜드 불일치
  - 상품명 기호 점검: 검색·이미지명에 불필요한 기호(`/` `|` `~` 등)를 경고로 알린다. 상품명은 고치지 않는다. 결과 화면 상품명 아래에 작성 주의 문구를 항상 표시한다.
- **모니터:** 표준 상품명 제안 (`모델명 크기 패널형태 패널 해상도 주사율 특징`). 크기·해상도 누락과 주사율 단위 누락을 탐지한다. 상품명에 없는 값은 중요요약에서 가져와 채우고 확인을 요청한다.

## 2단계 · 필드 생성

| 필드 | CPU | 모니터 |
|---|---|---|
| 브랜드 | `Intel® Core™ i5` · `Intel® Core™ Ultra 7` 표기. 서버는 모델 규칙으로 제안(`Intel® Xeon® 6` · `W` · `E`, 확인 요청) | — |
| 부가제목 | `※ 쿨러 포함/미포함 \| ※ A/S n년`. 쿨러는 판매구성에 명시된 경우만 포함 | — |
| 키워드 | 모델명 우선. 포괄어·유통어 제외, **다른 모델 번호 혼입 탐지**. 서버는 모델명·코드네임(붙여 쓴 형태 + 띄어 쓴 형태) 규칙으로 제안(확인 요청) | — |
| 중요요약설명 | **사양 DB에서 생성**. 현재값과 코어·스레드·L3를 대조 | 기존 값을 **표준 순서로 정렬하고 표기를 통일**. 필수 항목 누락과 상품명 불일치를 탐지 |

## 판정 표시

| 표시 | 의미 |
|---|---|
| 오류 | 등록값이 서로 충돌 |
| 확인 요청 | 담당 확인 후 수정 |
| 경고 | 표기·규칙 정리 |
| 확인불가 | 근거 없음, 값 생성 안 함 |
| 확인 | 규칙·DB와 일치 |

상태 칩은 색과 텍스트를 함께 표시한다(입력 대기 / 처리 중 / 결과 완료 / 확인 요청 n건 / 확인불가 n건 / 오류 n건).

## 설계 원칙 — Truth Protocol

이 도구의 핵심은 "빠름"이 아니라 **"틀린 걸 사실처럼 내놓지 않음"**이다.

- 사양값은 **사양 DB에 등록된 모델만** 생성한다. 미등록 모델은 값을 만들지 않고 "확인불가"로 표시한다.
- 사양 DB는 **Intel 공식 사양 페이지와 개별 대조**한 상태를 모델별로 표시한다(대조 완료 / 대조 전).
  - DB 구축 중 공식 대조로 **시드값 오류 3건을 발견해 교정**했다: 13100/13100F 최대 터보 전력, 코어 울트라 최대 메모리, 265 그래픽 클럭.
- 쿨러 동봉이나 A/S처럼 근거가 없는 항목은 추정하지 않고 담당자 확인을 요청한다.
- 모니터는 사양 DB가 없으므로 값을 새로 만들지 않고 정렬과 정규화만 한다.

## 완제품 PC · 노트북 (시리즈 한정)

- 대상: HP `GT18-0000KR`(HyperX OMEN 35L), `15-fb2055AX`(빅터스 15) 2개 모델. 담당자 등록본의 키워드 규칙과 중요요약 형식을 그대로 따른다.
- 상품명의 구성(RAM·SSD·OS)과 옵션(`[2TB SSD 추가]` → 3TB, `[128GB RAM 교체(32GB*4)]` → 128GB)을 읽어 키워드·중요요약에 반영한다. 등록본 3건과 글자 단위로 일치함을 확인했다.
- 구성 외 사양은 **담당자 등록본 기준이며 HP 공식 대조 전**이라 "확인 요청"으로 표시한다. 상품명이 잘렸거나 규칙에 없는 모델은 값을 만들지 않는다.

## 사양 DB 현황

- Intel 데스크톱 12·13·14세대, 코어 울트라 200S / 200S Plus, 61개 모델
- 이 중 36개는 Intel 공식 사양 페이지와 개별 대조 완료. 나머지(13700, 13700K, F·KF 파생 모델 등)는 화면에 "공식 대조 전 · 등록 전 확인"으로 표시한다.
- **서버 사양 DB:** Xeon 6 `6747P` · `6767P` 2개 모델(Intel 공식 사양 페이지 개별 대조 완료). 중요요약은 등록본 형식 그대로 생성하며, 6767P 생성값이 실제 등록값과 글자 단위로 일치함을 확인했다. 쿨러는 부가제목에 트레이(Tray) 표기가 있을 때만 `미포함`, 없으면 `[확인 필요]`. 시리즈 표기(`6700P 시리즈`)는 등록본 형식에 따라 모델 번호로 만든 값이다(Intel 페이지에는 시리즈명 표기 없음).
- **서버 키워드 규칙(DB 등록 모델):** `모델명, Xeon 모델명, Xeon모델명, PK오더코드, 영문 코드네임, 한글 코드네임(붙임), N코어, 서버CPU, 인텔, 제온, 제온6, 소켓`. 오더코드는 Intel 페이지에서 확인하지 못해 6767P만 담당자 등록값을 쓰고, 6747P는 비워 두고 확인을 요청한다.
- **미등록:** 10세대 이하, 위 2개를 제외한 서버 CPU 전체. 서버는 형식·세대 검증과 함께 브랜드·키워드를 규칙으로 제안하고(확인 요청), DB 미등록 모델은 중요요약 사양값을 생성하지 않는다. 10세대 이하는 값을 생성하지 않는다.

## 데이터 정책

- 단일 HTML. 백엔드와 외부 전송이 없고, 입력값과 캡처 이미지는 브라우저 안에서만 처리된다. 외부에서 받는 것은 글꼴, 인식 엔진, 인식용 한국어 데이터뿐이다.
- **회사 상품 데이터는 포함하지 않는다.** 공개된 모델 식별자와 제조사 공개 사양만 사용한다.
- 사용자 입력은 이스케이프 처리해서 출력한다.

## 접근성

키보드만으로 캡처 영역(Enter / Space)과 모든 버튼·입력을 쓸 수 있다. 포커스 표시, 판정의 색+텍스트 병기, 움직임 줄이기 설정(`prefers-reduced-motion`)을 지원한다.

## 로드맵

- 서버 CPU(Xeon) 사양 DB 모델 확대, 10세대 이하 데스크톱
- 카테고리 확장: 다른 제품군은 등록 예시 1건과 키워드 규칙이 있으면 추가 가능
- 연계 에이전트: CQO(상품 DB 품질·단종 검수) → CNO(등록 표준화) → GRIDIT(MD 전략)

## RAM · 일반화 범위 (11/6 추가)
- **RAM:** 담당자 등록본 2건(데스크탑 DDR5, 서버 DDR5)의 중요요약 형식을 글자 단위로 재현함을 확인했다. 값은 상품명에 있는 것(DDR 세대, 속도, 용량, CL)만 쓰고, PC5 번호는 속도×8로 계산해 상품명 표기와 대조한다. 램타이밍 상세·전압·히트싱크는 상품명에 없으므로 현재 중요요약에서 가져오거나 `[확인 필요]`로 표시한다.
- **RAM 키워드는 규칙 확정 전 제안**이다. 등록된 RAM 키워드 예시가 없어 다른 작업본의 순서를 참고했고, 브랜드는 상품명 앞 `[브랜드]`에서만 읽는다.
- **완제품 PC (등록본 없는 모델):** 키워드만 OMEN 규칙을 일반화해 제안하고 중요요약은 만들지 않는다.
- **노트북:** 등록본 1건(Victus)의 항목 순서를 다른 모델에 적용하되 값은 원본 그대로 유지한다.
- **모니터 키워드:** 규칙 확정 전 제안이다. 중요요약은 정렬·정규화만 한다.
- 헤더의 '지원 카테고리' 패널에서 지원 범위를 확인할 수 있다.

## AMD 라이젠 데스크톱 규칙 (11/6 추가)
- **브랜드:** `AMD Ryzen™ N` (티어는 상품명·브랜드에서 읽고, 없으면 모델 둘째 자리로 추정해 확인 요청).
- **부가제목:** `※ 쿨러 포함/미포함 | ※ 멀티팩 제품 | ※ A/S n년`. 멀티팩은 상품명 판매구성에 있을 때만 붙이고, `* 쿨러가 없는 멀티팩 제품 입니다 *` 같은 문구는 이 형식으로 바꾼다.
- **쿨러:** 상품명에 `쿨러미포함`/`쿨러포함`이 적힌 경우만 판정한다. 멀티팩이라는 이유로 추정하지 않는다.
- **키워드 순서:** 모델명 → `라이젠N 모델명` → `라이젠N` → `RyzenN` → `AMD` → 코드네임 → Zen 아키텍처 → 소켓 → (X3D면) `3D V캐시`. 예: `7800X3D,라이젠7 7800X3D,라이젠7,Ryzen7,AMD,라파엘,Zen4,AM5,3D V캐시`. 시리즈 규칙: 1000~5000 → AM4, 7000~9000 → AM5. G 접미 APU(2·3 시리즈)는 Zen 키워드를 넣지 않는다.
- **상품명:** 보존 모드. 참고안은 `모델 (코드네임) (판매구성)`이고, `/ 쿨러미포함` 같은 조건은 부가제목으로 옮기라고 알린다.
- **중요요약:** AMD 서식이 확정되지 않아 **생성하지 않고 현재값을 유지**한다. 현재값은 시리즈 규칙으로 아키텍처·세대·소켓·쿨러·코어/스레드 비율·3D V캐시만 대조한다. 사양 DB는 아직 없다.

## 사양 DB 미등록 모델 보강 (11/6)
사양 DB에 없어도 규칙으로 만들 수 있는 항목은 만든다. 확인되지 않은 세부 사양만 해당 항목에서 보류한다.
- **인텔 코어 티어:** 상품명에 `i9` 등이 없으면 12~14세대 모델 번호 규칙(세 번째 자리 1·3→i3, 4·5·6→i5, 7→i7, 9→i9)으로 브랜드·키워드를 만든다. 예: `14900KS` → `Intel® Core™ i9`.
- **서버 CPU 브랜드:** Xeon Scalable은 첫 자리로 등급을 정한다(8 Platinum · 6/5 Gold · 4 Silver · 3 Bronze). `8480+`처럼 `+`가 붙은 모델도 처리한다.
- **서버 키워드(DB 미등록):** Xeon 6와 Scalable의 담당자 키워드 순서를 모델명·코드네임·코어 수·등급 매핑으로 조합한다. 오더코드(PK)와 소켓은 확인된 값이 없어 넣지 않는다.

## 노트북 사양 DB · 캡처 인식 보강 (11/6)
- **노트북 사양 DB(`NB_SPEC_DB`):** 담당자가 확인한 중요요약을 모델 코드로 등록한다. 현재 `15UD50T-GX5JK`, `15ZD90RU-GX54K`, `NT750XGR-A51AG`, `NT750XGR-A38AS`, `NT940XGQ-A51AG`. 모델 코드가 같으면 상품명·입력에 없는 항목(안티글레어, 코어 수, 램 종류, 웹캠, 색상 등)을 DB에서 채우고, 입력·상품명 값(저장장치 교체 옵션 등)을 우선한다. 램 용량·CPU 모델이 DB와 다르면 오류로 알린다.
- **제품 라인명:** DB 모델은 DB의 라인명을 쓴다(캡처가 `울트라PC 듀얼업`을 `SEZIPC FEY`로 읽어도 브랜드는 `울트라PC`). DB에 없는 모델에서 캡처가 읽은 라인명에 한글이 없으면 인식 오류로 보고 브랜드·키워드에 쓰지 않는다.
- **캡처 인식 속도:** 고정밀 데이터 주소(`4.0.0_best_int`)는 파일이 없어(404) 매번 지연만 생겼다. 기본 모델만 쓰도록 바꿔 인식 엔진 준비가 1초 안에 끝난다. 기본 모델은 한글 상품명을 자주 잘못 읽으므로, 모델 코드(영문+숫자)를 기준으로 DB·규칙을 적용한다.
- **새 모델 등록:** 확인된 중요요약 한 줄을 `NB_SPEC_DB`에 모델 코드와 `line`(제품 라인명)과 함께 추가한다. 값은 등록본·제조사 공식 사양을 담당자가 확인한 것만 넣는다.

## 캡처 상품명 보정 (11/6)
기본 인식 모델은 한글 상품명을 자주 잘못 읽는다(예: `울트라PC 듀얼업` → `SEZIPC FEY`, `A51AG` → `ASTAG`). 캡처로 들어온 상품명은 등록된 상품명 목록(`NB_KNOWN_NAMES`)과 모델 코드로 대조해 바로잡는다.
- 모델 코드가 등록 모델과 2글자 이내로 같고 전체 문자열이 가장 가까운 상품명 하나를 고른다. 동점이면 추측하지 않는다.
- `+`·`교체`·`추가`·`설치` 옵션이 있으면 같은 모델의 다른 판매 상품일 수 있어 앞부분과 옵션은 인식값을 유지하고 모델 코드만 바로잡는다.
- 보정하면 상품명 칸도 함께 고치고 검증 결과에 "캡처 인식 보정 · 등록 상품명으로 교체"를 표시한다. 직접 입력한 상품명은 보정하지 않는다.
- 새 모델은 `NB_KNOWN_NAMES`에 등록 상품명을 추가하고, 사양은 `NB_SPEC_DB`에 추가한다.
- **상품명 칸 정리:** 원본 캡처의 상품명 줄은 `원본 캡처의 상품명 → 오른쪽 결과로 확인하세요` 안내와 함께 조금 작게(폭 72%) 보여 주고, 방법 2의 `상품명` 라벨은 없앴다(입력칸은 그대로). `방법 1`·`방법 2` 표시는 글자를 키웠다.
- **클릭 오류 수정:** 원본 상품명 줄이나 인식 상태 문구를 눌러도 입력·결과가 지워지지 않는다. 캡처 영역(점선 박스)을 누를 때만 이전 상품을 지운다.

## 제조사 태그와 상품명 (11/7)
상품명 앞의 `[LG전자]`·`[삼성전자]`·`[HP]`·`[인텔]`·`[AMD]`는 신관리자에서 제조사로 선택하는 값이라 상품명이 아니다. CPU·노트북·완제품 PC는 이 태그를 상품명에서 빼고 제조사 칸(기존 정보와 비교)으로 옮긴다. 캡처로 인식한 상품명은 입력칸에도 태그 없이 들어가고, 직접 입력한 경우 입력칸은 그대로 두며 결과의 상품명만 태그 없이 나온다. `[MD PICK]` 같은 홍보 태그는 제조사로 보지 않아 그대로 둔다. RAM·모니터는 기존 처리(브랜드 분리)를 유지한다.

## 키워드 규칙 정정 (11/6)
- 모니터 키워드에는 "모니터"를 붙이지 않는다(예: `27인치`, `커브드`). 예외는 `게이밍모니터`, `화이트모니터`, `사무용모니터`.
- RAM 중요요약은 담당자 등록본 형식을 따른다.
