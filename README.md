# CNO — Chief Naming Officer v2.1

상품 등록 표준화 에이전트. 상품명 **사실검증**과 **브랜드 · 부가제목 · 키워드 · 중요요약설명 자동 생성**을 한 화면에서 처리한다. **Romi Lab** · Rom Kim (romi4670)

**Live:** https://romi4670.github.io/cno/

## 무엇을 하나

이커머스 상품 등록에서는 상품마다 공식 사양을 찾아 키워드와 20여 항목의 중요요약설명을 직접 입력해야 한다. 담당자마다 표기가 다르고, 다른 상품의 값을 복사해 붙이거나 사양을 잘못 옮겨 적는 오류가 생긴다. CNO는 이 반복 입력을 **규칙과 검증된 사양 DB**로 대신하고, 등록 전에 사실 오류를 잡아낸다.

## 사용

두 가지 입력 중 **하나만** 쓰면 된다. 입력하면 바로 실행된다.

1. **방법 1 · 캡처 넣기:** 신관리자 상품정보·상품 목록 화면을 캡처해 끌어다 놓거나 `Ctrl+V`로 붙여넣는다(영역을 클릭할 필요 없음). 저장해 둔 이미지 파일은 **파일에서 선택**으로 올린다. 브라우저 안에서 글자를 인식해 상품명 등을 채운다. 인식된 **상품명 칸을 원본과 한 번 대조**한다.
2. **방법 2 · 상품명 입력:** 상품명만 입력. A/S 기간(확인된 경우만)과 쿨러 포함 여부는 보조 옵션으로 지정할 수 있다.
3. 필요하면 **기존 정보와 비교**를 펼쳐 현재 등록값(제조사·브랜드·부가제목·키워드·중요요약)을 넣는다. 키워드 혼입, 쿨러 충돌, 사양 불일치를 함께 점검한다.
4. 왼쪽 **등록용 결과**를 복사 버튼으로 관리자 화면에 붙여넣는다. 오른쪽 **검증 결과 및 근거**에서 판정과 근거를 확인한다.

화면 하단 **예제로 체험하기**는 실제 업무에서 나온 오류 유형을 공개 모델명으로 재현한 것이다.

### 캡처 인식 방식

- 캡처에서는 **모델 번호와 판매구성만** 사용한다. 한글 코드네임 등 나머지는 사양 DB와 규칙으로 생성하므로 인식 오류가 결과 값에 섞이지 않는다.
- 서버 형식 `(48C, 96T …)`의 글자 오인식은 "스레드 = 코어 × 1 또는 × 2"가 맞을 때만 자동 교정한다.
- 이미지는 외부로 전송되지 않는다. 인식 엔진(Tesseract.js)과 한국어 데이터를 **최초 1회 CDN에서 내려받는다.** 사내망에서 CDN이 막혀 있으면 캡처 입력이 동작하지 않으며, 이때는 방법 2를 쓴다.

## 1단계 · 상품명 검증

- **CPU: 보존 모드.** 현행 상품명 형식(`모델명 (코드네임) (판매구성)`, 서버 `모델 Processor (xC, yT, zM Cache, a.bc GHz)`)은 그대로 두고, **사실 오류만 '확인 요청'**으로 표시한다. 상품명은 자동으로 고치지 않는다(상품명은 담당 승인 사항).
  - 코드네임 사실 오류와 표기 변형, 서버 형식 내부 오류(`GHz` 띄어쓰기, 소수점)
  - 상품명 ↔ 부가제목 쿨러 충돌, 제조사 ↔ 브랜드 불일치
- **모니터:** 표준 상품명 제안 (`모델명 크기 패널형태 패널 해상도 주사율 특징`). 크기·해상도 누락과 주사율 단위 누락을 탐지한다. 상품명에 없는 값은 중요요약에서 가져와 채우고 확인을 요청한다.

## 2단계 · 필드 생성

| 필드 | CPU | 모니터 |
|---|---|---|
| 브랜드 | `Intel® Core™ i5` · `Intel® Core™ Ultra 7` 표기 | — |
| 부가제목 | `※ 쿨러 포함/미포함 \| ※ A/S n년`. 쿨러는 판매구성에 명시된 경우만 포함 | — |
| 키워드 | 모델명 우선. 포괄어·유통어 제외, **다른 모델 번호 혼입 탐지** | — |
| 중요요약설명 | **사양 DB에서 생성**. 현재값과 코어·스레드·L3를 대조 | 기존 값을 **표준 순서로 정렬하고 표기를 통일**. 필수 항목 누락과 상품명 불일치를 탐지 |

## 판정 표시

| 표시 | 의미 |
|---|---|
| 오류 | 등록값이 서로 충돌 |
| 확인 요청 | 담당 확인 후 수정 |
| 경고 | 표기·규칙 정리 |
| 확인불가 | 근거 없음, 값 생성 안 함 |
| 확인 | 규칙·DB와 일치 |

상태 칩은 색과 텍스트를 함께 표시한다(입력 대기 / 처리 중 / 결과 완료 / 확인 요청 n건 / 확인불가 n건 / 오류 n건).

## 설계 원칙 — Truth Protocol

이 도구의 핵심은 "빠름"이 아니라 **"틀린 걸 사실처럼 내놓지 않음"**이다.

- 사양값은 **사양 DB에 등록된 모델만** 생성한다. 미등록 모델은 값을 만들지 않고 "확인불가"로 표시한다.
- 사양 DB는 **Intel 공식 사양 페이지와 개별 대조**한 상태를 모델별로 표시한다(대조 완료 / 대조 전).
  - DB 구축 중 공식 대조로 **시드값 오류 3건을 발견해 교정**했다: 13100/13100F 최대 터보 전력, 코어 울트라 최대 메모리, 265 그래픽 클럭.
- 쿨러 동봉이나 A/S처럼 근거가 없는 항목은 추정하지 않고 담당자 확인을 요청한다.
- 모니터는 사양 DB가 없으므로 값을 새로 만들지 않고 정렬과 정규화만 한다.

## 사양 DB 현황

- Intel 데스크톱 12·13·14세대, 코어 울트라 200S / 200S Plus, 61개 모델
- 이 중 36개는 Intel 공식 사양 페이지와 개별 대조 완료. 나머지(13700, 13700K, F·KF 파생 모델 등)는 화면에 "공식 대조 전 · 등록 전 확인"으로 표시한다.
- **미등록:** 10세대 이하, 서버 CPU 전체(Xeon Scalable / 6 / W / E). 형식 검증과 세대 판정만 하고 사양값은 생성하지 않는다.

## 데이터 정책

- 단일 HTML. 백엔드와 외부 전송이 없고, 입력값과 캡처 이미지는 브라우저 안에서만 처리된다. 외부에서 받는 것은 글꼴, 인식 엔진, 인식용 한국어 데이터뿐이다.
- **회사 상품 데이터는 포함하지 않는다.** 공개된 모델 식별자와 제조사 공개 사양만 사용한다.
- 사용자 입력은 이스케이프 처리해서 출력한다.

## 접근성

키보드만으로 캡처 영역(Enter / Space)과 모든 버튼·입력을 쓸 수 있다. 포커스 표시, 판정의 색+텍스트 병기, 움직임 줄이기 설정(`prefers-reduced-motion`)을 지원한다.

## 로드맵

- 서버 CPU(Xeon) 사양 DB, 10세대 이하 데스크톱
- 카테고리 확장: RAM, 노트북, 완제품 PC
- 연계 에이전트: CQO(상품 DB 품질·단종 검수) → CNO(등록 표준화) → GRIDIT(MD 전략)
