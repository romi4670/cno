# CNO — Chief Naming Officer

상품명 검증·정규화 에이전트. 상품 등록/수정 시 상품명 규격 준수와 **모델↔코드네임 사실 정합성**을 검증한다. **Romi Lab** · Rom Kim (romi4670)

**Live:** https://romi4670.github.io/cno/

## 무엇을 하나

이커머스 상품 등록에서 상품명은 규칙 없이 담당자마다 제각각 작성되기 쉽다. CNO는 상품명을 **일관된 규격**으로 검증·정규화하고, 잘못된 코드네임처럼 사실과 어긋난 표기를 등록 단계에서 잡아낸다.

카테고리별 규칙을 플러그인처럼 확장하는 구조다. 현재 **CPU**와 **모니터**를 지원한다.

### CPU
- 상품명 규격 검증: `모델명 (정식 코드네임)` — 유통·상태·쿨러·스펙을 상품명에서 분리
- **모델↔코드네임 사실검증**: 인텔 코어 세대 규칙, Xeon 서버 규칙, AMD 라이젠/EPYC 규칙 기반 추론
- 중요요약설명(스펙 요약) 규격 정렬·검증

### 모니터
- 필수 항목(크기·해상도) 누락 탐지
- 주사율 `Hz` 단위 강제(밝기 값과 혼동 방지)
- 패널 표기 정규화(`IPS패널`→`IPS`), 카테고리 중복어·마케팅 문구 제거

## 설계 원칙 — Truth Protocol

이 도구의 핵심은 "빠름"이 아니라 **"틀린 걸 사실처럼 내놓지 않음"**이다.

- 코드네임 판정은 **규칙 기반 추론**임을 명시한다.
- 추론이 불확실한 모델(펜티엄/셀러론, 라이젠 APU, 코어 울트라, EPYC Dense 등)은 그럴듯한 값을 지어내지 않고 **"확인불가 → 수동검증"**으로 표시한다.
- 교차비교(2소스) 시 값이 **불일치하면 임의 선택하지 않고 반드시 플래그**한다.
- 확인 안 되는 스펙은 넣지 않는다(허위 스펙 금지).

## 데이터 정책

- 단일 HTML, 백엔드·외부 전송 없음. 입력값은 브라우저 안에서만 처리된다.
- **회사 상품 데이터는 포함하지 않는다.** 공개된 것은 검증 **방법론과 규칙 엔진**뿐이다.
- 예제(프리셋)는 공개된 제품 식별자(모델명·코드네임·스펙)만 사용한다.

## 사용

`index.html`을 브라우저로 열거나 Live URL 접속. 제조사/브랜드/상품명 등을 붙여넣고 검증하면, 규격 위반·사실 오류를 4단계(오류/경고/확인불가/확인)로 판정하고 표준 상품명을 제시한다.
